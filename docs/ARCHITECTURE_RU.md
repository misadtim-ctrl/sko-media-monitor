# Архитектура системы

## Выбранный вариант

Используется гибрид `Google Sheets + Apps Script + Python в GitHub Actions`.

| Вариант | Ежедневная работа | Надёжность 24/7 | Масштабирование | Стоимость | Поддержка |
|---|---|---:|---:|---:|---:|
| Только Apps Script | очень просто | средняя, жёсткие квоты | низкое | бесплатно | просто |
| Локальный Python | неудобно, компьютер должен работать | низкая | среднее | бесплатно | средне |
| Платный сервер | удобно | высокая | высокая | платно | сложно |
| Telegram-бот без таблицы | удобно для чтения | средняя | среднее | бесплатно | теряется рабочая таблица |
| Выбранный гибрид | привычная таблица и каналы | высокая для бесплатной схемы | высокая | бесплатно | умеренно |

Apps Script отвечает за привычный интерфейс, основной обход, Google News, личное меню бота и окончательную доставку в главный канал. GitHub Actions даёт больше времени и памяти для ручного глубокого поиска, локальной модели, OCR и будущего отдельного мониторинга Instagram. Python не имеет права публиковать в главный канал. Токен Telegram остаётся только в защищённых свойствах Apps Script.

По актуальной документации GitHub стандартные hosted runners бесплатны для публичных репозиториев: <https://docs.github.com/en/actions/concepts/billing-and-usage>. Для обычного Google-аккаунта Apps Script ограничен 90 минутами триггеров и 20 000 URL Fetch в сутки: <https://developers.google.com/apps-script/guides/services/quotas>. Поэтому тяжёлая обработка вынесена из Apps Script.

GitHub автоматически отключает расписания публичного репозитория после 60 дней без активности: <https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows>. Чтобы владельцу не приходилось следить за этим вручную, отдельное ежемесячное расписание создаёт крошечное служебное обновление репозитория.

## Контуры

### Республиканский

Главный канал ведёт проверенный Google-бот: он использует исходный словарь СКО, районов, сёл и областных объектов, проверяет сайты и Google News. Региональные СМИ жёстко исключены из основного канала. Python может создать только закрытый диагностический отчёт и не доставляет материалы в этот канал.

### Ежедневный мониторинг

Проверяет городские и общественные профили, доступные Threads, VK, Facebook и TikTok-ссылки. Официальные новостные сайты и аккаунты в этот контур не входят. Категории: дороги, ЖКХ, благоустройство, животные, паводок, транспорт, экология и происшествия.

#### Instagram собирается на Mac, а не в облаке

Instagram блокирует IP-диапазоны дата-центров ответом `429` уже на первом профиле, и паузы с ротацией этого не лечат. Проверено 26.07.2026: одна и та же сессия из GitHub Actions получает `429`, а с домашнего Mac спокойно отдаёт данные. Поэтому в облаке Instagram выключен целиком (`INSTAGRAM_ENABLED=false`), сессия туда больше не передаётся, а городские паблики собирает сам Mac.

Сбор идёт **через ленту подписок**, а не обходом профилей. Один запрос к ленте возвращает свежие посты всех пабликов сразу, поэтому:

- проверка идёт раз в 10 минут вместо раза в час — пост попадает в канал, пока он ещё свежий;
- расход падает примерно с 3700 запросов в сутки до 300, и аккаунт не подходит к порогу блокировки.

Лента ранжированная, а не строго хронологическая, поэтому теоретически может пост не показать. Страховка — `INSTAGRAM_SWEEP_PROFILES`: за каждый прогон дополнительно проверяются два профиля по очереди, весь список обходится примерно за два часа.

**Список подписок аккаунта и есть конфигурация мониторинга** — лента отдаёт только то, на что подписан аккаунт. Паблики, попавшие в ленту, но отсутствующие в реестре, видны в отчёте полем `feed_unknown`; в ленту также попадают рекомендации Instagram от аккаунтов вне подписок, и они отсеиваются по реестру.

Запуск: `instagram-schedule.command` ставит агент launchd `kz.sko.monitor.instagram`. Пока Mac спит, сбор не идёт; если он молчит дольше трёх часов, Apps Script присылает предупреждение в Telegram.

Второй бесплатный путь — Meta Business Discovery — в коде уже поддержан ([instagram.py](../src/sko_monitor/collectors/instagram.py)) и включается заполнением `META_ACCESS_TOKEN` и `META_IG_USER_ID`. Он работает и из облака, но покрывает только Business/Creator-профили, поэтому заменить локальный сбор целиком не может.

### Региональные СМИ

Остаются отдельным контуром для позитива и ручного поиска за период. Они не могут попасть в республиканский Telegram-канал.

## Семантический анализ

Первый слой — высокополнотные правила на русском и казахском с учётом корней и контекста. Второй слой — бесплатная локальная модель `paraphrase-multilingual-MiniLM-L12-v2`. При недоступности модели мониторинг не падает и продолжает работу на первом слое.

Для изображений применяется Tesseract OCR. Для видео предусмотрены кадры через FFmpeg и локальный faster-whisper. Медиа скачиваются во временный каталог и удаляются сразу после анализа.

## Доставка и отказоустойчивость

Для главного канала Apps Script сам пишет находки в таблицу и ставит сообщения в защищённую очередь Telegram. Python используется для ручного поиска по историческому периоду и диагностических отчётов; его результаты не могут попасть в главный канал без отдельного изменения кода и явного разрешения.

Apps Script пишет строки в нужный лист и ставит сообщения в скрытую очередь. Тексты новостей постоянно не хранятся. Для защиты от повторов остаются только короткие ключи: нерелевантные 14 дней, доставленные релевантные ссылки 365 дней.

Состояния очереди: `pending`, `sending`, `retry`, `sent`, `skipped`. После ответа Telegram `200 OK` записываются URL-ключ и ключ `источник + заголовок`. При `429` используется `retry_after`, при сетевых ошибках — увеличивающаяся задержка.

Отказ одного источника не останавливает остальные. После трёх часов без heartbeat Apps Script сообщает владельцу, но основной Google-мониторинг продолжает работать.

## Границы бесплатной схемы

Это максимальная практическая надёжность без платной инфраструктуры, но не коммерческий SLA. GitHub может задержать плановый запуск, Instagram может потребовать обновить сессию, а удалённую до очередной проверки публикацию восстановить невозможно. Перекрытие 72 часа и независимый Apps Script заметно уменьшают риск пропуска.
